# 數據及資料應用說明

## 資料儲存架構

所有資料儲存於 Amazon DynamoDB（AWS NoSQL 資料庫），共 8 張資料表：

| 資料表 | 主鍵 | 用途 | 資料性質 |
|--------|------|------|---------|
| Accounts | account_id | 使用者帳號、個人資料、角色、綁定碼、同意紀錄 | 長期保留 |
| Facts | fact_id | 結構化記憶卡片（AI 自動萃取的生活資訊） | 長期保留，持續更新 |
| FactHistory | history_id | 記憶卡片修改歷史（每次 update 保留舊值） | 長期保留 |
| Sessions | session_id | 對話 session 元資料 | 長期保留 |
| Messages | message_id | 對話逐輪訊息紀錄（含 extracted 旗標） | 保留 30 天 |
| DailySummaries | account_id#date | AI 生成的每日摘要與每週總結 | 長期保留 |
| Follows | follow_id | 追蹤關係（照護者↔長輩的綁定） | 長期保留 |
| HealthKnowledgeBase | — | 衛教知識庫條目 | 靜態資料 |

## 資料流向

```
長輩語音/文字輸入
    ↓
[STT 語音辨識] → 文字
    ↓
[Bedrock 第一次呼叫] → AI 回覆文字
    ↓                        ↓
[Polly TTS] → 語音播放   [Bedrock 第二次呼叫] → 記憶操作 JSON
                              ↓
                    [程式碼執行寫入] → Facts 表 + FactHistory 表
    ↓
Messages 表（逐輪保存）
    ↓
[每日摘要觸發] → Bedrock → DailySummaries 表
    ↓
[每週總結觸發] → Bedrock → DailySummaries 表（summary_type: weekly）
    ↓
照護者後台查閱
```

## 記憶卡片（Facts）資料模型

每張記憶卡代表長輩的「一件當前狀態事實」：

```json
{
  "fact_id": "uuid",
  "account_id": "使用者 Cognito Sub ID",
  "category": "用藥",
  "content": "每天早上吃氨氯地平 5mg 控制血壓",
  "track": true,
  "extracted": true,
  "updated_at": "2026-07-30T14:30:00+08:00"
}
```

**category 固定七種枚舉：** 飲食、活動、睡眠、用藥、身體、情緒、其他

**設計特性：**
- 可變當前狀態模型（非 append-only 流水帳）
- 同一件事永遠只有一張卡，update 時舊值進 FactHistory
- track = true 代表 AI 應主動追蹤進展

## 衛教知識庫

`HealthKnowledgeBase` 表儲存照護相關衛教資料：

```json
{
  "title": "高血壓飲食注意事項",
  "category": "飲食",
  "content": "建議減少鈉的攝取，每日鈉攝取量不超過 2000mg...",
  "keywords": ["高血壓", "鈉", "鹽", "飲食"],
  "source": "衛生福利部",
  "source_url": "https://..."
}
```

**使用方式：** 每次對話時以關鍵字/正則表達式比對使用者訊息，命中的條目注入 AI 回覆的上下文，確保回答具備專業照護知識基礎。

## 資料蒐集範圍

| 資料類型 | 蒐集方式 | 來源 |
|---------|---------|------|
| 對話文字紀錄 | 自動（每輪對話存入） | 使用者語音/文字輸入 |
| 生活資訊事實卡 | 自動（AI 萃取） | 從對話內容中辨識 |
| 個人資料（姓名、生日、身高、體重） | 手動填寫 | 使用者在個人資料頁輸入 |
| 健康資料（慢性病、用藥、過敏） | 手動填寫 | 使用者在個人資料頁輸入 |
| 個人備註 | 手動填寫 | 使用者自行編輯 |

## 資料安全與存取控制

### 傳輸層
- 所有 API 通訊走 HTTPS（TLS 加密）
- WebSocket STT 連線走 WSS（加密 WebSocket）

### 認證與授權
- 使用者身分驗證由 AWS Cognito 處理（OAuth 2.0 + JWT）
- 每個 API 請求需攜帶有效的 id_token（Bearer Token）
- 後端逐請求驗證 JWT 簽章、有效期、audience

### 存取控制（權限檢查）
- 長輩只能存取自己的資料（依 JWT 中的 sub claim 判斷）
- 照護者查看長輩資料前，必須通過追蹤關係權限檢查（status = approved）
- 綁定機制採雙重驗證（帳號代碼 + 6 碼授權碼）

### 儲存層
- DynamoDB 預設啟用靜態加密（AWS managed key）
- 資料儲存於 AWS 區域資料中心，不離開指定區域

### 資料保留政策
- 對話逐輪訊息：保留 30 天後清除
- 事實卡片與摘要：長期保留（照護參考用途）
- 使用者可隨時要求完整刪除所有資料
