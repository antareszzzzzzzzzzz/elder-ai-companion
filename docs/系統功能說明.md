# 系統功能說明

## 一、核心模組

---

### Module A — 語音互動陪伴

**用途：** 以自然語音對話方式陪伴長者，提供情感支持與日常互動，降低獨居長者的孤立感。

**輸入：**
- 長者的語音（透過麥克風，經 STT 轉為文字）
- 或長者的文字輸入（鍵盤打字）

**輸出：**
- AI 助手「小安」的文字回覆
- 語音朗讀（文字經 TTS 合成為語音自動播放）

**操作流程：**
1. 長輩進入聊天主畫面
2. 點擊「按住說話」按鈕 → 系統開始錄音 → 即時顯示辨識文字
3. 放開按鈕 → 辨識文字自動送出
4. 等待 AI 回覆（顯示打字動畫）
5. 回覆出現 → 自動語音朗讀（可關閉）
6. 長輩可繼續對話或結束

**情境感知能力：**
- 時間感知：注入當前台灣時間，依時段調整問候
- 記憶感知：參考過往對話萃取的事實卡
- 主動關懷：對 track=true 的事項，AI 會主動詢問進展
- 知識庫：比對衛教資料，回答健康問題時引用專業內容

**安全機制：**
- 禁止編造醫療資訊（system prompt 最高優先鐵律）
- 無法確認的健康問題引導使用者諮詢專業人員

---

### Module B — 生活記錄與智慧摘要

**用途：** 從對話中自動辨識長者的生活資訊，結構化儲存為記憶卡片，並每日生成摘要供照護者掌握近況。

#### B-1：自動生活資訊擷取

**輸入：** 每輪對話的使用者訊息 + AI 回覆

**輸出：** 記憶操作指令（新增/更新事實卡）

**操作流程（自動，無需人工介入）：**
1. 長輩與小安對話
2. 每輪對話結束後，系統自動呼叫第二次 LLM
3. LLM 分析對話內容，判斷是否有新的生活資訊
4. 產出 add/update 操作 → 程式碼驗證後寫入 Facts 表
5. 記憶卡片在長輩的個人資料頁面即時顯示

**擷取的資訊類別：** 飲食、活動、睡眠、用藥、身體、情緒、其他

#### B-2：每日摘要生成

**輸入：** 目標長輩當天所有更新過的事實卡

**輸出：** 一段自然語言的每日生活摘要

**操作流程：**
1. 照護者在後台點擊「產生每日摘要」
2. 系統取得該長輩今日所有事實卡
3. 依類別分組後送入 Bedrock
4. AI 歸納為一段溫暖親切的摘要文字
5. 儲存到 DailySummaries 表，顯示在時間軸上

#### B-3：每週總結生成

**輸入：** 目標長輩過去 7 天（或所有現有的）每日摘要

**輸出：** 一段整合性的本週總結

**操作流程：**
1. 照護者在後台點擊「產生本週總結」
2. 系統取得該長輩今天之前的所有每日摘要
3. 若有 7 天以上 → 取最近 7 天；不足 → 取全部
4. 將每日摘要文字送入 Bedrock，要求歸納趨勢
5. 儲存到 DailySummaries 表（summary_type = "weekly"）

#### B-4：每日摘要自動推播

**用途：** 讓照護者不必每天記得手動產生摘要，設定一次時間後由系統自動完成，
並主動通知，降低長期使用的負擔。

**輸入：** 照護者設定的推播時間（HH:MM，台灣時間 UTC+8）

**輸出：**
- 自動產生的每日摘要（寫入 DailySummaries）
- 站內通知（照護者頁面的通知鈴鐺）
- Email 通知（寄送至照護者於 Cognito 註冊的信箱）

**操作流程：**
1. 照護者進入長輩的「專屬照護區」→「AI 摘要紀錄」分頁
2. 勾選「啟用自動推播」並選擇時間 → 儲存設定
3. 系統將時間記錄於該筆追蹤關係（Follows 表）
4. 後端背景排程每 60 秒檢查一次是否有到期項目
5. 條件成立時自動產生摘要，並寄出 Email、亮起通知鈴鐺
6. 照護者點擊通知可直接跳至該長輩的摘要頁面

**觸發條件：** 「現在已過設定時間」**且**「當天尚未產生摘要」。

採用此條件而非「現在剛好是設定時間」有兩個好處：伺服器若在設定時間點
未運行，之後啟動時會自動補產生當天摘要，不會整天遺漏；同時具備天然的
去重效果，重複檢查不會產生兩份摘要，也不會重複寄信。

**多位照護者的處理：** 同一位長輩若被多位照護者追蹤且各自設定不同時間，
由於摘要本身是共用的（DailySummaries 主鍵為 `account_id#date`），系統取
所有設定時間中最早者作為觸發點，產生後寄送給全部已設定排程的照護者。

**通知機制設計：** 站內通知不額外建立資料表，由前端查詢當天是否已有摘要，
並以瀏覽器端記錄已讀狀態；Email 收件地址從 Cognito 以使用者 `sub` 反查，
不需在資料庫另存 email。

> 註：Email 功能在開發環境受 Amazon SES 沙箱模式限制，收件地址需事先驗證。
> 詳見 `技術限制與未來規劃.md`。

### Module C — 照護者資訊介面

**用途：** 提供照護者或家屬可查看的後台頁面，快速掌握長者健康近況。

**包含資訊：**
- 長者基本資料（姓名、帳號）
- 累計 AI 互動次數
- 記憶卡片總覽（依類別分色顯示）
- AI 生成之每日摘要紀錄（時間軸格式）
- 本週總結（時間軸中以不同顏色區分）
- 跨日洞察（近 7 天重複模式分析）
- 每日摘要自動推播設定（時間設定，見 B-4）
- 通知鈴鐺（追蹤請求 + 每日摘要通知）

**操作流程：**
1. 照護者登入 → 選擇照護者角色
2. 在首頁輸入長輩帳號代碼 + 6 碼綁定碼 → 送出綁定請求
3. 長輩在個人資料頁核准請求
4. 照護者首頁出現家人卡片 → 點入進入「專屬照護區」
5. 切換三個 Tab 查看不同資訊
6. 可觸發生成每日摘要 / 本週總結 / 跨日洞察

## 二、進階模組

---

### 知識庫建置

**用途：** 收錄照護與衛教相關資料，讓 AI 回應具備專業照護知識基礎，避免純靠通用知識回答。

**輸入：** 衛教文件內容（人工匯入 HealthKnowledgeBase 表）

**輸出：** 當使用者提問相關健康話題時，知識庫匹配內容注入 AI 回覆上下文

**操作流程：**
1. 管理者透過 seed 腳本將衛教 PDF/文本內容結構化後存入資料庫
2. 每次對話時系統自動以關鍵字比對使用者訊息
3. 命中的知識條目附加到 system prompt 中
4. AI 優先參考知識庫內容回答，並可引述來源

---

### 主動關懷機制

**用途：** 模擬真實照護者的行為，讓 AI 不只被動回答，還會主動追蹤長者的健康變化。

**運作方式：**
- 事實卡有 `track` 標記，由萃取 LLM 語意判斷設定
- track=true 的事項在下次對話時注入獨立區塊
- AI 開場主動關心其中一件（不會一次問完全部）
- 事項解決後 LLM 自動將 track 改為 false

---

### 使用者同意機制

**用途：** 滿足個資保護要求，確保使用者在使用前明確了解資料蒐集範圍。

**操作流程：**
1. 長輩首次登入時，系統顯示全螢幕同意書
2. 同意書以白話文說明資料蒐集、儲存、分享對象、刪除權利
3. 下方列出技術性資料安全說明（加密、存取控制、保留政策）
4. 按下「我同意，開始使用」→ 記錄同意時間戳 → 進入系統
5. 未同意前無法使用任何功能

---

## 三、系統角色

| 角色 | 可用功能 |
|------|---------|
| 長輩（elderly） | AI 聊天、個人資料編輯、記憶卡片查看、綁定碼管理、追蹤請求核准 |
| 照護者（caregiver） | 綁定長輩、查看長輩健康總覽、觸發摘要/總結/洞察、設定提醒 |

角色存在後端資料庫，可隨時切換，登出再登入後記得上次選擇。

---

## 四、綁定機制

**目的：** 確保只有經過長輩授權的家人/照護者才能查看其健康資料。

**流程：**
1. 長輩在個人資料頁面查看/自訂 6 碼綁定授權碼
2. 長輩將帳號代碼 + 綁定碼告知照護者
3. 照護者在綁定 Modal 輸入帳號代碼 + 6 碼 → 送出
4. 後端驗證綁定碼是否正確 → 正確則建立追蹤關係（pending 狀態）
5. 長輩在個人資料頁看到追蹤請求 → 點擊「核准」
6. 狀態變為 approved → 照護者可查看長輩資料

**安全性：** 雙重驗證（碼 + 核准），即使知道帳號也無法未經授權存取。
